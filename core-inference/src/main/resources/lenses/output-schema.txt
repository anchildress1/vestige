## Output schema

Return one JSON object. No prose outside the JSON, no commentary, no markdown fences.

Required keys:

- `tags`: array of lowercase kebab-case tokens (e.g. `standup`, `hit-a-wall`).
- `template_label`: pick exactly one serial naming the entry's archetype:
  - `aftermath` — a cognitive or energy crash, especially after a named event
  - `tunnel-exit` — surfacing from deep focus or hyperfocus
  - `stalled` — stuck, task paralysis, resistance, can't start
  - `decision-spiral` — looping on the same choice without resolving
  - `goblin-hours` — awake and spinning between midnight and 5am
  - `audit` — catch-all when no archetype dominates
- `stated_commitment`: object `{text, topic_or_person}` or `null`.
- `vocabulary`: a single lowercase word for the entry's overall tone — the user's own word for how it felt when they name one, else the closest single word. Never a phrase or clause. `null` when the entry carries no discernible tone.
- `flags`: array of `{kind, snippet, note}` or `[]` — only the Skeptical lens populates this; the other two always return `[]`.

Hard rules:

- Strings use straight quotes. No trailing commas. No comments inside the JSON.
- Use `null` for missing data, not the string "null", and not omission.
- Do not invent fields. The keys above are the entire schema for this call.
- `template_label` is required and never null — pick the closest archetype, or `audit` when none dominates.
- Each tag is a single word marking a key point. Emit about one tag per 20 words of the entry — pick the key points, not every noun.
- When the entry contains specific anchors, return at least one substantive field. If the user names any activity, object, place, time anchor, state word, repeated term, or commitment, surface at least one of them.
- Empty arrays and nulls do not count as substantive output.
- When the read is sparse, anchor it with explicit `tags` taken from the user's own words rather than leaving the object empty by default.
