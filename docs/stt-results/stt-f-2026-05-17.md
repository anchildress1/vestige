## Verdict

**FAIL — premise false. `litertlm-android:0.11.0` enforces exactly one live session per Engine.**

The concurrent 3-lens fan-out (`coroutineScope { async }.awaitAll()` over independent
`createConversation` contexts) does **not** work. Only the lens that won the race to the engine
completed; the other two threw `FAILED_PRECONDITION` instantly and contributed "no opinion". The
2-of-3 resolver fallback masked the collapse as `outcome=SUCCESS` — without this probe it ships
green while silently running **1 lens, not 3**.

Stories 2.6.6 + 2.19 Path C and ADR-008 §Correction (2026-05-16) are superseded by this evidence.
v1 ships **sequential** 3-lens on one serialized session (ADR-008 §Addendum 2026-05-17). The
Story 2.19 non-blocking-foreground goal is **SDK-impossible** on 0.11.0 and is withdrawn.

## SDK error (verbatim)

```
Failed to create conversation: FAILED_PRECONDITION: A session already exists.
Only one session is supported at a time.
Please delete the existing session before creating a new one.
```

## Per-lens evidence

| Lens | Attempts | Elapsed | Parsed | Note |
|---|---|---|---|---|
| LITERAL | 2 | 95 ms | ✗ | `FAILED_PRECONDITION` ×2 — no forward pass |
| INFERENTIAL | 2 | 92 ms | ✗ | `FAILED_PRECONDITION` ×2 — no forward pass |
| SKEPTICAL | 1 | 14 739 ms | ✓ | won the session race; only real inference |

The ~95 ms LITERAL/INFERENTIAL figures are **rejection latency** (two native
`createConversation` round-trips that throw), not fast inference. SKEPTICAL's 14.7 s is the true
single-lens cost (175-char prompt → 540-char reply, MTP on, E4B GPU). Sequential 3-lens therefore
projects to ≈ 3 × ≈ 44 s/entry — within the documented 25–55 s GPU band.

## Resolution

- Engine: `callMutex` serializes every call — one live conversation/session at a time.
- Worker: sequential `LENSES.map { runLens }`; concurrent fan-out removed.
- Test: `BackgroundExtractionWorkerTest."lenses run sequentially, never concurrently — SDK is single-session"` pins the contract (max-in-flight == 1, LENSES order).

### Post-fix re-probe (commit `cebfb561`, same device, GPU)

**PASS — 3/3 lenses parsed, no `FAILED_PRECONDITION`.**

| Metric | Concurrent (broken) | Sequential run A (`cebfb561`) | Sequential run B (`b14d042b`) |
|---|---|---|---|
| lenses parsed | 1 / 3 | **3 / 3** | **3 / 3** |
| model_calls | 5 (2 wasted on rejects) | **3** (no retries) | **3** (no retries) |
| LITERAL | ✗ 95 ms (rejected ×2) | ✓ 9 103 ms, 1 attempt | ✓ 8 958 ms, 1 attempt |
| INFERENTIAL | ✗ 92 ms (rejected ×2) | ✓ 8 946 ms, 1 attempt | ✓ 9 398 ms, 1 attempt |
| SKEPTICAL | ✓ 14 739 ms | ✓ 13 326 ms, 1 attempt | ✓ 13 938 ms, 1 attempt |
| wall_clock | 14 766 ms (1 real lens) | **31 403 ms** (3 real lenses) | **32 315 ms** (3 real lenses) |
| pss_delta | ~413 MB | ~354 MB | ~288 MB |
| outcome | SUCCESS (masked) | SUCCESS (legitimate, 3/3) | SUCCESS (legitimate, 3/3) |

**Reproducibility:** two sequential runs land at 31.4 s / 32.3 s — sub-second per-lens jitter,
both inside the documented 25–55 s E4B-GPU band. SKEPTICAL is the consistent long pole
(~13–14 s, 540-char output) vs LITERAL / INFERENTIAL ~9 s (~320-char) — prompt/output-length
driven, not noise. `pss_delta` 288–354 MB is allocation/GC variance, no growth trend, well
under the ~4.85 GB resident engine. The concurrent "win" was illusory — it ran one lens and
discarded two. Sequential is correct and the only buildable shape on `0.11.0`.

This run is the on-device validation cited by [ADR-014](../adrs/ADR-014-foreground-background-split-and-periodic-pattern-analysis.md)
§"Validated by" — it locks the foreground/background split (only the foreground call blocks the
user; 3-lens analytics + periodic pattern analysis run async) precisely because sequential
3-lens at ~32 s cannot sit in the synchronous path.
